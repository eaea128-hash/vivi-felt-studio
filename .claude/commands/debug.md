# Skill: Debug First（Vivi 版）

**觸發時機**：回報 bug、「沒有效果」、「顯示不對」、「點了沒反應」

## 執行步驟

1. **重現問題**：確認完整描述
   - 哪個頁面（URL）？
   - 什麼操作？
   - 什麼現象（截圖最好）？
   - 手機還是電腦？

2. **縮小範圍**：

   | 現象 | 優先看 |
   |------|--------|
   | 版面跑版 / 元素重疊 | Browser DevTools → Elements → Computed CSS |
   | 按鈕沒反應 | Console 錯誤 → JS 是否有報錯 |
   | 表單送不出去 | Network tab → Formspree / GAS 請求狀態 |
   | 圖片不顯示 | img src 路徑是否正確，大小寫是否一致 |
   | 頁面空白 | Console 紅色錯誤，通常是 JS 語法錯誤 |
   | 手機版異常 | DevTools → Toggle Device → 確認 breakpoint |

3. **Vivi 常見已知問題優先確認**：
   - navbar 蓋住內容 → 確認 `body padding-top`（R-08）
   - 表單送出沒收到 email → 確認 Formspree ID `xrervybz`（R-04）
   - anchor 連結點了沒跳 → 確認目標元素有 `id`（R-07）
   - 按鈕點了頁面跳頂部 → `href="#"` 未替換（R-10）
   - CSS 樣式未生效 → 是否有重複定義（R-09）

4. **讀取相關檔案**：只讀問題相關區段，不全文掃描

5. **提出假設**：列 2-3 個可能原因，標注最可能的

6. **最小修復**：最小改動解決問題，不順手重構無關程式碼

7. **驗證方式**：說明如何確認問題已解決

## 禁止行為

- 未確認根因前不開始修改
- 不同時修改超過 2 個不相關的地方
- 不猜測性修改（改了不知道為什麼）
- 不修改 `styles/style.css` 全域變數來解決單頁問題
